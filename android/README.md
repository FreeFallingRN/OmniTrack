# OmniTrack Android Application

Native Android client built with Kotlin, Jetpack Compose, Room SQLite cache, and WorkManager background sync.

## Specifications

- **Architecture**: MVVM with Offline-First Repository Pattern
- **Instant Actions**: Low-latency persistent notification with `[+1]`, `[-1]`, and `[Switch]` quick actions.
- **Share Target**: Intercepts `ACTION_SEND` (webnovel links) with an OpenGraph metadata parser sheet.
- **Discord Sharing**: Customize fields and preview Markdown from an entry's share button. The share style is selected in Settings; covers are attached when available, with text-only sharing if loading fails.
- **Sync**: Supabase REST integration with local Room caching and WorkManager background sync.

`MainActivity` wires the library ViewModel, separate AniList, MangaBaka and Moon+ Reader sync owners, settings state holder, scrape-report repository, and media lookup services. Feature owners schedule their existing background work; the library ViewModel owns library and progress state.

Entry aliases are edited separately from shared series aliases. After upgrading, refresh the library and reopen a series entry before editing if its cached aliases have not yet been separated. If creating an entry only partially succeeds, check the refreshed library and complete its details before retrying; refresh manually if reconciliation fails.

Pulling down on the home library refreshes Supabase and synchronizes linked Moon+ Reader and MangaBaka entries, plus AniList when auto-sync is enabled. Concurrent sync requests for the same tracker share the active run.

## Release channel and logging

Settings defaults to Stable. Switch to Beta to enable live logging to Logcat; returning to Stable turns live logging off. The centralized logger keeps up to 1 MiB of redacted entries in memory, and saves the current buffer to the app's backup-excluded storage on a fatal error. Beta Settings can inspect and export recent entries or the last saved fatal log, even when live logging is off. Logging calls should avoid sensitive data and supply known secrets for redaction; pattern-based redaction cannot guarantee removal of every secret.

With Beta live logging enabled, Settings can start or stop optional Grafana Loki uploads and send a test log, with a separate result for that request. Configure `GRAFANA_LOKI_TOKEN` in the build environment or `android/local.properties`; GitHub releases use the `GRAFANA_LOKI_TOKEN` repository secret. Optional `GRAFANA_LOKI_URL` and `GRAFANA_LOKI_USER` build settings override the default endpoint and user. Settings can save a token override in app-private, backup-excluded DataStore or clear it to use the build token. The override is not encrypted, and a token embedded in an APK can be extracted by anyone with the APK; use a restricted, revocable Loki credential. Uploads must be started again after an app restart, but the token need not be re-entered. Logs can contain sensitive information despite redaction. Uploads are limited to 64 KiB per batch and 512 KiB per start, including retries, with 64 KiB reserved for fatal uploads. Failed batches remain in the bounded in-memory queue and retry with backoff; when full, unprotected entries may be discarded and the status reports it. Pending entries survive stopping and restarting uploads within the process, but not an app restart. When the upload limit is reached, restart uploading to retry retained entries. Fatal errors also attempt a separate immediate upload with a three-second timeout, bypassing normal cooldown and active uploads; saving the fatal log locally is attempted independently of upload success.

## Moon+ Reader progress

In Settings → Moon+ Reader, select a progress backup/sync folder for `.po` files and use **Link books** to link matching chapter entries. The separate EPUB storage folder is used to find local `.epub` files. Adjust the chapter before applying to calibrate future checks; linked books can be unlinked on the same screen. Unlinking clears their saved link and calibration without changing reading progress or history. Checks run when the app resumes (at most once per minute), or use **Sync now**. Linked books are also checked periodically in the background, no more often than every 15 minutes and when network connectivity is available; Android controls the actual timing. The saved folders must retain read permission. Subfolders, including hidden ones, are scanned. Automatic checks read only linked `.po` files and skip files whose available modification time and size have not changed since successful processing. Files without a reliable modification time are reread. Links, positions and calibrations are stored locally on the device. Matches use the book filename and entry titles. Ambiguous and unmatched files can be linked manually to unlinked chapter-based novels; unmatched files can also be added as new novels. The link dialog adds one to Moon+'s zero-based spine chapter index and applies a per-entry offset, initially calibrated to current progress, including zero. Adjust the chapter before applying if needed. Each spine item, including interludes and unnumbered chapters, counts as a sequential step. Automatic sync only advances progress for a newer position and preserves entry status. A comic linked to MangaBaka is controlled by MangaBaka rather than Moon+ Reader; novels can use Moon+ Reader even when linked to MangaBaka. Unlink the active progress source before manually decreasing progress. Sync reports skipped links and read errors; background runs report partial outcomes instead of success. Synced changes use the import history source and pending Supabase writes are queued for retry.

## MangaBaka library

Use Settings → MangaBaka to connect with OAuth or a personal access token and fetch your library. Importing a MangaBaka series URL as a new chapter-based novel or comic links it to your library, adding it to MangaBaka if needed. If linking fails, the OmniTrack entry is still saved and a message is shown. Search and filter titles, add one as a new entry, or link it to a matching chapter-based entry with an optional offset. Links and offsets are stored on this device; linking itself does not change progress. MangaBaka syncs progress for comics only; novel links do not lock or update progress. Comic sync adds the offset to MangaBaka's chapter and only advances progress, using the import history source. A known total marks an entry completed when reached for a completed or cancelled series. Manual progress in the detail sheet is locked for linked comics; unlink before manually decreasing progress. When relinking after a reset, choose an offset that reflects the desired progress. Sync reports skipped links and errors, and background partial runs do not report success. Use **Sync now** or resume the app; automatic checks are debounced to once per minute. Connected accounts with linked entries are also checked in the background at least 15 minutes apart when network connectivity is available; Android controls the timing. Comic progress is saved locally after Supabase accepts the update. New entries are saved to Supabase. Sign in again when authorization expires. Data and covers are provided by [MangaBaka](https://mangabaka.org/) and its [source providers](https://mangabaka.org/developers/concepts/data-and-sources).

MangaBaka series URLs are imported through its public API. Existing library status and comic progress prefill the editor; new MangaBaka library entries are added when the OmniTrack entry is saved. The chapter total is displayed in the editor; it and the description are not currently saved on media entries.

Changing the status of a linked entry in its detail sheet saves it locally and sends it to MangaBaka, including for linked novels. Failed writes are queued for retry.

## AniList library

In Settings → AniList, connect in a browser and use **Sync & match** to link unambiguous title matches to episode-based anime entries. Search and filter the library, link existing entries, or add titles as new entries. Batch import includes anime movies and single-episode titles, and skips possible duplicates and titles missing required metadata for manual review; initial imports are non-active. Link an anime from its detail menu by selecting AniList and searching the connected library. Linked entries use their AniList URL and lock manual episode editing until unlinked; sync never decreases progress and later increases count as tracking activity. AniList list statuses map to OmniTrack statuses. Sync fills missing covers without replacing existing covers and stores positive episode totals locally on the device; metadata updates do not record consumption history. Cover and URL uploads are queued for retry when offline. Use **Sync now** or enable automatic sync for resume and periodic background checks when network connectivity is available. Unlink entries from their detail menu or Settings. Disconnecting removes credentials but retains device-local links for that account. Credentials are encrypted in Android Keystore-backed storage excluded from backups; reconnect if authorization expires or is revoked.

Changing a linked entry's status in its detail sheet saves it locally and sends it to AniList. Failed writes are queued for retry, even when automatic progress sync is disabled.

## Scrape issue reports

Use the flag in a URL-imported draft to save a report, then open Settings → Scrape reports to inspect, copy, or delete it. Reports are stored locally first and uploaded when a network is available; deletions also sync. Run the database migrations before using sync. Reports include the original and normalized URLs, scraped draft, tags, and note: avoid including sensitive information. Like the existing personal-backend tables, reports can be read and modified by anyone with the Supabase anon key.
